# TeamFlow — Learning Log

## What I'm Doing

Building one product end-to-end to become a product engineer. 

**Product:** TeamFlow. A lightweight project management tool for small e-commerce product and ops teams.

**Why this product:** I chose it because it forces real engineering. Domain modeling, permissions, data relationships, failure modes. 

---

## How I'm Learning

**Loop:** Identify Problem, Think, Design, Build, Break, Analyze, Rebuild, Validate, Next Problem

**Rules I set for myself:**
- Understand the problem before proposing solutions.
- State problems as pain.
- Do not build features because they sound useful. Build because the problem demands it.
- Design comes before code.

---

## Day 1 — Domain Research

My first step was to understand the user before designing anything. I did not write code today.

### The Story I Studied

Priya is a Product Manager at a 40-person online clothing store. Customer support tells her the discount code is broken on mobile. She reads it, gets pulled into a meeting, and forgets to write it down. Two days later a customer complains again. She messages a developer to fix "the discount code thing." He guesses wrong. Three days lost.

### The Problem I Identified

**Work requests get lost because there is no single place to record them with an owner.**

### What I Learned

1. Before software, before categories, before notifications, the first job is to write it down in one place immediately.
2. Every request needs an owner.
3. A feature is only worth building if a real problem demands it.

[Domain research comes before design.]

### Mistakes I Made

1. I answered the problem with software features before finishing my understanding of the problem.
2. I proposed progress updates every hour or every 6 hours. Nobody asked for that. It would create noise.
3. I wrote the problem as activity ("managing important business tasks") instead of as pain.

### What I Corrected

1. Understand the problem fully before jumping to solutions.
2. Only build what the problem demands.
3. State problems as pain.
